\section{System Use-Case Diagram}

\subsection*{Use cases}

Every use case has one control class, because section D asks for each
sequence diagram's use case to be represented by a control class. The goal of
each use case is a result of value to its actor. FR-11 (database storage)
applies to every use case that saves data; it is listed on the two use cases
where the data is created.

\subsection*{Actors}

The actors are Customer, Flight Agent and Administrator. All three are
specialisations of the abstract actor User, which is the actor of Login
(UC-01).
