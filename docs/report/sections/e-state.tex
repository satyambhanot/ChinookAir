\section{State-Transition Diagrams}

Each state diagram has one initial node (the black dot) and a final node
(the dot in a circle). Every transition is labelled with an event, and with a
guard in square brackets where a state has more than one way out.

\subsection*{The state of the whole system}

The diagram below shows the life cycle of the application. It starts
in \texttt{Starting}, where it opens the database. If that fails it goes to
\texttt{Error}, shows a message and ends. Otherwise it checks the month in
\texttt{CheckingPromotion}. In a new month it shows the promotion in
\texttt{ShowingPromotion}, and in the same month it goes straight to
\texttt{LoggedOut}. From \texttt{LoggedOut} the user submits a login and the
system is \texttt{Authenticating}. Invalid credentials return to
\texttt{LoggedOut}. Valid credentials lead to the composite state
\texttt{LoggedIn}, into the session state for the role of the user. The
transitions \texttt{logout} and \texttt{exit} belong to \texttt{LoggedIn}, so they
apply to all three session states. \texttt{exit} is also possible from
\texttt{LoggedOut}. The application ends in \texttt{Closing}, which closes the
database, and then in the final state.

\subsection*{The state of a payment}

The diagram below shows one Payment record. Its four states are the values of
the payment status in the class diagram. A new Payment is created in
\texttt{Pending}. When the simulated authorization accepts it, the Payment calls
\texttt{approve()} and becomes \texttt{Approved}. When the authorization rejects
it, the Payment calls \texttt{decline(reason)} and becomes \texttt{Declined}. An
approved Payment can later be refunded, which happens when its reservation is
cancelled or changed to a different price, and then becomes \texttt{Refunded}.
Nothing leaves \texttt{Declined} or \texttt{Refunded}: the arrows to the final
node need no event. If a customer tries again after a declined payment, the
system creates a new Payment, so a record never goes back to \texttt{Pending}.
This matches the payment activity diagram and the sequence diagram of the
payment.
